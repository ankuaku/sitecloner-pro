SiteCloner Pro — Documentation

Introduction

SiteCloner Pro is a self-hosted web app that downloads the complete frontend of any web page from a single URL — including sites built with React, Vue, Angular, Next.js and Nuxt.

A real browser loads the page, waits until it has finished building itself, scrolls it to load lazy content and records every file it received. The visitor gets a ZIP with two copies:

  • static/ — an exact, frozen, editable copy: HTML + CSS + images + fonts, no JavaScript. Opens with a double-click.
  • interactive/ — the site's own JavaScript and every response it loaded (scripts, code-split chunks, fonts, images and GET API data), replayed offline by a service worker. Menus, sliders, tabs and client-side page routing keep working.

Requirements

  • Node.js 20 or newer (22 LTS recommended)
  • Any Linux / Windows / macOS server or a host like Render, Railway, a VPS or Docker
  • About 300 MB free disk (more if you allow large clones)
  • 1 GB RAM minimum (2 GB recommended) for the Smart engine

Shared PHP hosting (cPanel without Node.js) cannot run this app.

Installation

unzip sitecloner-pro.zip && cd sitecloner-pro
npm install
cp .env.example .env     # then edit .env
npm start

Open http://localhost:3000 for the tool and http://localhost:3000/admin for the admin panel.

Admin panel

Log in at /admin. Settings are saved instantly to data/settings.json — no restart needed.

  • Overview — successful and failed clones, running jobs, queue size, whether the render engine is installed.
  • Branding — site name, logo letters, primary colour, tagline, footer and terms text.
  • Limits — max pages, total size (MB), max files, time limit, clones per hour per visitor, how long ZIPs are kept, Render mode switch, maintenance mode and a blocked-domain list.
  • Ads & code — HTML/JS for an ad above and below the tool (AdSense etc.) and code for <head> (Google Analytics, verification tags).
  • Recent clones — last 50 clones with URL, result and visitor IP.

Logged-in admins bypass the hourly limit and maintenance mode, which is handy for testing.

Engines & outputs

EngineHow it worksBest for
Smart (default)Headless Chrome renders the page, scrolls it, waits for images and fonts, then captures the live DOM and every network response.React, Vue, Angular, Next.js, Nuxt, Svelte, MUI/Emotion/styled-components, Tailwind, any modern site.
FastDownloads the HTML the server sends and its assets over plain HTTP. No browser, very light.Static sites, WordPress, landing pages, low-RAM servers.

What the Smart engine preserves in the static copy:

  • CSS-in-JS rules that only exist in the browser's CSSOM (styled-components, Emotion/MUI, JSS) and constructable stylesheets
  • Open shadow DOM (web components), saved as declarative shadow DOM
  • Canvas drawings and charts, converted to images
  • Form values, checked boxes and selected options
  • Lazy-loaded and JavaScript-inserted images; for responsive images with many sizes, the size actually shown is kept to avoid huge downloads
OutputOpens withJavaScript
Static + Interactiveboth folders in one ZIP—
Static onlydouble-click index.htmlremoved (clean, editable)
Interactive onlySTART-WINDOWS.bat, node serve.js, or upload to Netlify/Vercel/any https hostoriginal, working

The interactive copy uses a service worker, which browsers only allow on http://localhost or https://. That is why it ships with a tiny zero-dependency serve.js and Netlify/Vercel rewrite files. Requests that send data (POST: logins, checkout, forms) still go to the original server.

Turn the Smart engine on or off in Admin → Limits. Puppeteer is installed with npm install and downloads Chrome automatically; the Docker image uses system Chromium. Each Smart clone uses one Chrome instance (~250 MB RAM), so keep MAX_CONCURRENT at 2 on a 1 GB server.

Deployment

Render.com

  1. Push the folder to a GitHub repository.
  2. In Render choose New → Blueprint and select the repository. It reads render.yaml and builds the Dockerfile.
  3. Enter ADMIN_PASSWORD when asked. A disk is mounted at /app/data so settings survive deploys.

VPS (Ubuntu) with PM2 + Nginx

curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs nginx
npm install && sudo npm i -g pm2
pm2 start ecosystem.config.cjs && pm2 save && pm2 startup

Nginx site config:

server {
  server_name yourdomain.com;
  client_max_body_size 1m;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 180s;
  }
}

Then add HTTPS with sudo certbot --nginx.

Docker

docker build -t sitecloner .
docker run -d -p 3000:3000 --env-file .env -v $PWD/data:/app/data sitecloner

Customisation

  • Page text, sections and FAQ: public/index.html
  • Colours, spacing, fonts: public/static/style.css (the primary colour is also set from the admin panel)
  • Front-end behaviour: public/static/app.js
  • Clone engine: src/cloner.js — e.g. add more lazy-load attributes in the image section

Security

  • SSRF protection: every page, asset and redirect is checked; private, loopback, link-local and cloud-metadata addresses are refused. Keep ALLOW_PRIVATE_NETWORK=false on a public server.
  • Limits: per-file 25 MB, per-clone total size, file count and time limit, per-IP hourly limit, queue cap.
  • Admin: login is rate-limited (10 tries / 15 min), cookie is signed, HTTP-only and SameSite=strict.
  • Clean-up: ZIPs are deleted after the time set in the admin panel.
  • Blocked domains: add banks, payment providers or any brand you don't want cloned on your service.

Tell your users (the terms checkbox does this) to clone only sites they own or have permission to copy. Website designs, logos and text are normally protected by copyright and trademark law.

Troubleshooting

The clone is blank or missing content. You used the Fast engine on a JavaScript site — choose the Smart engine.

Interactive copy shows "Loading clone…" or a blank page. It was opened by double-click (file://). Use START-WINDOWS.bat / node serve.js, or upload it to a host.

Some items in the interactive copy are empty. Data that the page would only fetch after a click or search was never loaded during cloning, so it is not in the copy.

"HTTP 403" on the first page. The site blocks automated requests (e.g. Cloudflare bot protection). These sites can't be cloned.

Admin keeps logging out after restart. Set a fixed SESSION_SECRET in .env.

Rate limit hits everyone at once behind a proxy. Set TRUST_PROXY to the number of proxies in front of the app.

"Failed to launch the browser". On Linux install Chrome libraries (sudo apt install -y chromium) and set PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium, or use the Docker image.
